使用场景 · 供应商主体核验

采购前，先确认供应商究竟是哪一家企业

报价单上的简称、英文商号和合同上的工商主体，未必指向同一家企业。供应商尽调的第一步，是把交易对象确认清楚。

查看 OpenAPI连接 Remote MCP

Remote MCP 是供客户端配置的 Streamable HTTP 端点，不是网页查询表单。

先核对企业主体，再购买证据

中国企业核验不能只看名字像不像。品牌名、简称、翻译名可能混用，同名候选也可能存在。AI采购智能体如果直接选第一条结果，就可能把别家公司的中标或监管记录关联到你的供应商。

统一社会信用代码（USCC / Unified Social Credit Code）用于识别目标企业主体。18位字符格式正确，只说明输入满足格式规则，并不证明代码确实属于这家供应商。应把代码与中文法定名称一起核对。

  1. 先用免费 resolve_china_company，传入中文 company 名称，检查当前配置范围内的主体候选。免费解析不接受 uscc 参数。
  2. 若有多个候选，不自动猜测。向交易对方取得准确法定名称和统一社会信用代码，确认 intended legal entity。
  3. 再把已确认的 uscc 交给 Basic 或 Full，保留返回的关联状态；证据不足时允许暂停或转人工。

中国供应商核验的价值不只是返回一个名称，而是让后续机器可读证据有明确的关联对象。来源定位信息（provenance）能帮助采购人员复查智能体引用的依据。

工具价格何时使用
resolve_china_company免费 / Free按 company 名称解析主体并检查歧义；多个候选时先取得准确 USCC，再使用付费工具。

无需注册，无需 API Key，无需预充值账户。 x402 · Base USDC. 付费调用仍需要兼容且有余额的钱包与明确支出授权。

Full 的 include_evidence 默认 true；evidence_limit 为 0–100 的整数。记录是否存在及返回多少，以来源覆盖和响应中的 evidence_meta 为准。

示例结构，不是实时事实

示例结构：摘取当前公开 Full 请求 schema 的部分约束，不是企业查询结果，也不是完整可执行请求。没有填写真实企业名称或代码。Basic/Full 的 company、uscc 至少提供一个；免费解析要求 company。

{
  "type": "object",
  "properties": {
    "company": {
      "type": "string",
      "minLength": 2,
      "maxLength": 200
    },
    "uscc": {
      "type": "string",
      "minLength": 18,
      "maxLength": 18,
      "pattern": "^[0-9A-Z]{18}$"
    }
  },
  "anyOf": [
    {
      "required": [
        "company"
      ]
    },
    {
      "required": [
        "uscc"
      ]
    }
  ]
}

静态说明 / example；not_live_query。它只是 schema 摘录或来源字段投影，不是完整成功响应，不能用来证明任何企业的当前情况。
