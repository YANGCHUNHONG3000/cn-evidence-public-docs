使用场景 · 行政处罚与监管证据

评估供应商合规前，先看监管记录的原文与时间

企业风险评估需要有依据的事实，也需要保留不知道的部分。单条监管记录、同名匹配或历史处罚，都不应直接变成自动拒绝供应商的结论。

查看 OpenAPI连接 Remote MCP

Remote MCP 是供客户端配置的 Streamable HTTP 端点，不是网页查询表单。

把处罚记录、监管流程和当前结论分开

行政处罚是监管记录的一类；经营异常流程记录并不必然是一项处罚决定。开展供应商合规核验时，应先读记录类型、处理结果和时间，再决定它是否与审批规则有关。

存在历史处罚记录 ≠ 自动判定当前不合格。历史流程记录也不能自动说明当前经营异常。若来源没有明确确认当前状态，应保留 UNKNOWN，不能用猜测填满结论。

  1. 先核对企业主体。同名处罚记录在关联依据不足时应保持待确认，不自动绑定。
  2. 保留证据来源、数据集定位、checked_at 和处理状态。原始记录确有处罚机关、决定文号或日期时再引用，不要求模型补齐缺失字段。
  3. 由你的 Agent 按审批政策处理已确认事实：需要时核验更新来源、补充材料或交给人工复核，而不是让聚合结果替代最终企业尽调判断。

CN Evidence 是独立的证据聚合服务，不是政府运营的 API，不自动给企业贴“高风险”标签，也不出具无处罚或合规证明。
